# Feature: Auth, Session, and Password Recovery Security
Status: completed | Branch: feat/auth-session-password-security

## Specs

- **S1**: Audit and ensure that authentication and sessions work securely across the web app and the Chrome extension ("Solo deja las correciones de seguridad que hemos hecho al inicio de autenticaciones y sesiones").
- **S2**: Resolve the incongruence in "las lineas 21 a 24 de `src/lib/supabaseClient.ts`" (`setSupabaseAccessToken`) using Option A ("avanzamos con la opcionA para que de paso todo quede de forma ordenada para no prestar a confusión"): stop calling `setSupabaseAccessToken` from `syncExtensionToken` in the Web App so Supabase Auth manages HTTP headers and Realtime auth natively on the web, and restrict `setSupabaseAccessToken` strictly to the Chrome Extension Popup (`chrome-extension://`) where only the bridged JWT (`clipsync_access_token`) exists without a `refresh_token`.
- **S3**: Validate JWT expiration (`exp`) in `src/lib/jwt.ts` (`isJwtExpired`) and when hydrating sessions in `src/context/authContext.tsx` and `public/content.js`, guarantee local state cleanup on `signOut()` even on network failure, and tighten `isClipSyncApp()` in `public/content.js` against arbitrary `.vercel.app` subdomains.
- **S4**: Add the "forget password" option and a dedicated `/reset-password` page following the project's structure: "Necesito que le agregues al proyecto la opción de "forget password". Todo tiene que seguir la misma estructura del proyecto al agregar la nueva función. Debes de asegurarte de que el correo se mandado al usuario y redirigido a la una nueva pestaña que tambien debe ser creada, de reset password. Que contenga validaciones de longitud y seguridad. El usuario en ningun momento debe de ser capaz de ingresar a otra pagina de la misma app sin estar antes logueado y con nueva contraseña."
- **S5**: Display inline confirmation below the form when sending the reset password email without navigating back to login: "quiero que te fije que al mandar el email, vuelve a la parte de login. Quiero que se quede dentro de la pestaña de reset y debajo del mismo form, aparezca el texto de email enviado. Que no se vea debajo como con las demás notificacions".
- **S6**: Prevent race conditions that inadvertently redirect recovery users to `/login` and then `/` (Dashboard): "además de que me manda directamente al dashboard sin hacer el reset del password."
- **S7**: Transform technical rate limit errors into user-friendly messages that clearly reference repeated attempts and isolate them strictly below the form without duplicate bottom notifications: "fijate en que si el usuario intenta varias veces, que el mensaje del error aluda a eso. Ya que actualmente el mensaje es de rate limit. Quiero que sea más claro para el usuario" / "fijate que sale el mensaje tanto debajo del formulario como en la parte inferior de la app. Quiero que solo salga debajo del formulario".
- **S8**: "Solucionado, ahora quiero que corrijas la seguridad de la constraseña a restaurar. Utiliza los estilos de la skill /stageshow para demostrarle al usuario qué tan fuerte es la contraseña. Que el mensaje salga debajo del formulario, NO en la parte inferior de la aplicación.. Si tienes dudas, primero PREGUNTAME, no tomes decisiones por tu cuenta ni supongas. Esta pagina tiene que tener test para asegurar que sea una contraseña correct en formato. Verificar en caso de que NO sea correcta. Los mensajes de errores correspondientes. En caso de retornar al login, que se muestra tal pagina, en caso de guardado nueva contraseña, que se muestre el mensaje y se muestre el dashboard como pagina actual"
- **S9**: "Quiero que le agregues el mensaje de si hay match o no en la contraseña"
- **S10**: "Fijate que los errores coincidan, ya que he ingresado una contraseña que no hace match pero el mensaje principal que sale es \"Password must include at least one number\""
- **S11**: "Arregla la verificación de la contraseña, ya que vamos a dejar que el tener número en la contraseña sea opcional. Mientras sea dentro de los parámetros de good, se puede utilizar"
- **S12**: "Perfecto, ahora arregla que a haber hecho un recovery, vaya directamente al dashboard y que aparezca una ventana que diga que la nueva contraseña ha sido guardada con exito. El recuadro debe tener un logo de escudo haciendo referencia a la seguridad y debe de desaparecer luego de unos segundos"
- **S13**: "Quiero que revises que luego de mandar el reset del password, no me redirigue al dashboard"
- **S14**: "Espera, quiero que revices una última cosa. El mensaje de contraseña actualizada se muestra incluso si el usuario solo inició sesión"
